    Introduction

    This document is both the report template and its showcase. Every component a report needs is demonstrated below, in the order you would typically use it.

    The file is fully self-contained: fonts, icons, styles and scripts are embedded, so it renders identically offline, from an e-mail attachment or from a shared drive. Nothing is downloaded when it opens.

    Purpose

    Use this template for client deliverables, internal studies, audit reports and technical notes. It favours readability first: a comfortable line length, a clear heading hierarchy and generous spacing.

    What is inside

    A top bar with the document title and buttons to show the table of contents, number the headings, switch the theme and print; a document header with title, subtitle and metadata; an automatic table of contents; and a set of content components — including code blocks with a copy button and expanders — described in the following sections.

    Typography

    The text face is Plus Jakarta Sans, a modern geometric sans-serif with excellent legibility at reading sizes. Code uses JetBrains Mono. Both are embedded in the file.

    Heading levels

    The document title is the only h1. Sections start at h2 and nest down to h5. Levels h2 to h4 appear in the table of contents and can be numbered automatically.

    A level-four heading

    Level-four headings structure a sub-section into a few named parts. Keep them short; they introduce one idea each.

    A level-five heading

    Level five is a small, uppercase label. Use it for side topics, definitions or a short series of named paragraphs. It does not appear in the table of contents.

    Paragraphs and inline text

    Body text is set at a comfortable size with a generous line height. Inline styles cover strong emphasis, emphasis, links, highlighted passages and small print for secondary remarks.

    Paragraphs are kept to a readable measure of about seventy characters, which keeps long reports pleasant to read on wide screens.

    Navigation and themes

    The page helps the reader find their way through long documents.

    Table of contents

    The table of contents is generated when the page opens, from every h2, h3 and h4. On wide screens it sits in a sticky sidebar and highlights the section being read; on smaller screens it appears after the document header. It is not printed.

    On wide screens, the first button of the top bar hides the sidebar to centre the text, and brings it back. The choice is remembered for the next visit.

    Heading numbers

    Sections are numbered 1, 1.1 and 1.1.1, in the text and in the table of contents. The numbering button in the top bar, next to the theme button, shows or hides the numbers: the document sets the default, and the reader's choice is remembered for the next visit. Printed pages keep the numbering shown on screen.

    Light and dark themes

    The page follows the reader's system preference. The theme button in the top bar switches between light and dark, and the choice is remembered for the next visit.

    Printing

    The print button opens the browser's print dialog — so do Ctrl + P, or Cmd + P on a Mac — where the document can also be saved as PDF. Printed pages always use the light theme, leave out the top bar and the table of contents, open every expander and add page numbers.

    Callouts and badges

    Status components draw the reader's attention to what matters. They share four pastel tones — information, success, warning and error — chosen to stay distinct from each other and from the accent colour, in both themes.

    Callouts

    A callout sets a remark apart from the text around it. Give it a short title and keep it to a few sentences; it can hold links, lists or code.

    Reporting period

    The figures in this report cover January to September 2026. The detailed breakdown is in the tables below.

    Milestone reached

    Security hardening is complete: the 18 recommendations of the spring audit are implemented and verified.

    Budget under pressure

    The data platform migration has used 78% of its budget at 71% progress. A revised estimate is expected by mid-November.

    Decision needed

    Billing automation is blocked until the payment provider delivers its new interface. The steering committee must choose between:

    • extending the contract with the current provider, or
    • postponing the go-live to the first quarter of 2027.

    Badges

    Badges label a status or a category in a word or two: Planning On track At risk Blocked. A neutral and an accent variant cover everything else: Draft Featured.

    A leading dot makes a status easy to scan in dense lists and tables: Live Degraded Down Unknown.

    Badges in headings New

    Badges scale with the text around them, so they also fit in headings and table cells. A badge in a heading is left out of the table of contents.

    Figures and tables

    Figures and tables are numbered automatically, in order of appearance. Their caption sits underneath and holds only the description: the number is added for you.

    Figures

    A figure holds an image or an inline SVG illustration with its caption. Illustrations drawn with the template's fig-* classes follow the light and dark themes.

    Tables

    Wrap each table in a table-wrap block so it scrolls sideways on small screens instead of overflowing the page. Right-align figures with the num class, and close the table with a total row when the figures add up.

    Code and lists

    Code

    Inline code such as data-numbered marks names, values and file names. Longer extracts go in a code block, which scrolls sideways on narrow screens and wraps on paper:

    <div class="callout callout--success" role="note">
  <svg class="icon callout__icon" aria-hidden="true">
    <use href="#icon-success"/>
  </svg>
  <div class="callout__body">
    <p class="callout__title">Milestone reached</p>
    <p>Security hardening is complete.</p>
  </div>
</div>

    Every code block gets a Copy button in its top-right corner: it appears when the pointer is over the block or when the button has keyboard focus, and stays visible on touch screens. It copies the code exactly as written. Add data-no-copy to a pre to leave the button out.

    Keyboard keys use the kbd element: press Ctrl + F to search the document.

    Lists

    Bulleted lists group related points; numbered lists describe a sequence. Both can be nested.

    • One idea per item, kept short
    • Nested items for detail
      • a second-level item
      • another second-level item
    • Parallel wording from one item to the next
    1. Collect the figures for the period.
    2. Draft the analysis:
      1. write the key messages first;
      2. support each message with a figure or a table.
    3. Send the draft for review.

    Checklists

    A checklist shows what is done and what remains:

    • Figures reconciled with accounting
    • Charts and tables numbered
    • Management summary approved
    • Final PDF sent to the client

    Expanders

    An expander tucks away detail that not every reader needs — methodology, raw figures, long lists, reference material — behind a one-line summary. It is a native details element: it works without the script, the browser's find-in-page searches its hidden content, and a link to anything inside it opens it.

    Single expanders

    Keep the summary short and specific, so the reader can decide from it whether to open the expander. Add the open attribute to show an expander open when the page loads.

    Methodology and data sources

    Figures come from the finance ledger, closed on 30 September 2026, and from the project tracking tool. Budgets are the amounts approved at the start of each project; spend includes committed orders.

    • Progress is reported by each project owner and reviewed monthly.
    • Satisfaction is the average score of the quarterly client survey (112 answers).
    Expander markup Open by default

    A summary line and a body; code blocks inside an expander get their copy button too:

    <details class="expander">
  <summary>Methodology and data sources</summary>
  <div class="expander__body">
    <p>…</p>
  </div>
</details>

    Grouped expanders

    Wrap expanders in an expander-group block to join them into a single list, for questions and answers or a series of appendices. Give them the same name attribute and opening one closes the others.

    Why is the data platform migration at risk?

    Spend runs ahead of progress: 78% of the budget is used at 71% completion, mainly because the legacy data required more cleansing than estimated.

    When will billing automation resume?

    As soon as the payment provider delivers its new interface, announced for December. If it slips again, the go-live moves to the first quarter of 2027.

    Who approves the revised estimates?

    The steering committee, at its meeting of 18 November 2026, on a proposal from each project owner.

    Printed pages and PDFs show every expander open, so nothing is hidden on paper.

    Separators and layout

    Separators

    A separator marks a change of topic inside a section. The default line fades out at both ends around a small accent node.

    The dotted variant is lighter, for a pause rather than a change of topic.

    The labelled variant names what follows: a new part, the detailed findings, the appendices.

    Detailed findings

    Use separators sparingly: headings remain the main structure of the document.

    Two-column layout

    The grid-2 block sets short content side by side and stacks it on narrow screens.

    Strengths
    • Security hardening delivered on time and on budget
    • Client satisfaction up to 4.6 out of 5
    Watch points
    • Billing automation blocked by a supplier
    • Data platform spend ahead of progress

    Back to top

    Once the reader has scrolled past the first screen, a button in the bottom-right corner brings them back to the top of the document. It is not printed.

    How to use this template

    Start from a copy of this file and change only its content region:

    1. Replace everything between the REPORT:CONTENT:START and REPORT:CONTENT:END comments with your own document header and article. Leave the rest of the file — styles, scripts, embedded fonts — untouched.
    2. Set the document title in the <title> element, in the top bar (topbar__title) and in the footer (site-footer__title), and the date in the footer.
    3. Keep a single h1 and start sections at h2. Add data-numbered to the article to number headings by default, data-no-toc to keep a heading out of the contents, and data-toc-title to rename the contents.
    4. Build the body from the components above, copying their markup from this file. Figure and table numbers and code copy buttons are added automatically.

    Keep it self-contained

    Embed images as inline SVG or data: URIs and never link to external resources; otherwise the document no longer renders offline or from an e-mail attachment.
